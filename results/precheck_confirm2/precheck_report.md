## 6. 코드 정의

**(a) 비용(hop당 camera·s)**
- `VisibilityModel.cost`(`ccpilot/predictors.py`)는 탐색 집합의 크기를 잰다. 탐색 집합은 질의 hop의 예측 가시성 행렬 P(카메라 × 시간 칸)에서 확률이 τ 이상인 (카메라, 칸) 쌍이다(τ는 TAU_MIN = 1e-12 아래로 내려가지 않음). 비용은 그 쌍의 수에 Δ = 5초를 곱한 값이다.
- 행렬의 범위:
  - 행(카메라): 출발 카메라에서 2,500 m 안의 카메라, 출발 카메라 자신, 학습 기간에 그 출발 카메라 다음에 실제로 관측된 카메라의 합집합(`candidate_sets`)
  - 열(시간 칸): 퇴장 후 0 ~ T_max = 600초를 Δ = 5초로 나눈 120칸
- **멈추지 않는다.** 탐지 여부와 관계없이 τ 이상인 칸 전체를 센다. 표적을 찾으면 탐색을 멈추는 규칙은 없다.
- 탐지(hit)는 실제로 보인 (카메라, 칸) 가운데 하나라도 확률 ≥ τ인 것이다(`score` = 그 최댓값 ≥ τ).
- 행렬은 가장 세밀한 조건 키(출발 카메라 → 구역 → 시간대 → 속도 순 계층에서 학습에 있었던 가장 깊은 키)의 것이다.

**(b) 이탈 구역 4방위**
- 구역은 카메라 중심에서 출구점(관측 반경 안 마지막 보간점)으로의 각 rel = atan2(Δy, Δx)로 정한다. 지역 평면 좌표에서 x는 동쪽, y는 북쪽이다. 운동 방향(heading)이 아니라 출구점의 위치 각이다.
- 기준각 0° = 동쪽, 반시계 방향이다.
  - 동: −45° ≤ rel < 45°
  - 북: 45° ~ 135°
  - 서: 135° ~ 225°
  - 남: 225° ~ 315°
  - 식: `zone = floor(mod(rel + π/4, 2π) / (π/2)) mod 4` → 0 = E, 1 = N, 2 = W, 3 = S(`events.extract_sightings`)

**(c) 같은 시드에서 피드백 마스크가 같은가**
- **같다(한 실행 안에서).** `evaluate.run`은 실행마다 `rng = default_rng(seed)`의 첫 난수로 `fb_mask = rng.random(n_test) < 0.3`을 한 번 만든다. 이 마스크를 ACI 세 변형, MVP 세 변형(mvp_log 포함), qr_ogd, 모든 예측기에 함께 넘긴다.
  - static, Mondrian, qr_groups, Spatula식, CityTrac식, 사후 기준은 피드백을 쓰지 않는다.
- MVP의 무작위화도 같은 seed로 따로 초기화한다.
- 실행 사이(예: 목표만 바꾼 실행): 평가 hop 집합과 정렬이 같으면 마스크도 같다.
  - 다만 평가 hop 정렬(`sort_values("t_exit")`)이 안정 정렬이 아니다. 그래서 hop 집합이 바뀌는 시나리오 사이에서는 마스크가 조금 달라질 수 있다(POSTHOC.md 공통 주의).
  - 같은 자료·같은 시드에서는 결과가 재현된다. 7절의 시험 실행이 탐색 기간 1의 커밋된 요약 122행과 차이 0으로 같았다.

**(d) 기존 확증 실험의 시드**
- 사전 등록 확인 실험은 **평가 시드 1개(seed = 0)**다(`configs/porto_cctv_confirm.yaml`의 `eval.seed: 0`).
- 사후 시드 반복은 0, 1, 2, 3, 4의 5개다(`posthoc_seeds.py`, `results/porto_cctv_confirm_posthoc/seeds_prereg25/`).

  - 환경: 노트북 WSL, 24스레드, 단일 프로세스

  - 재현 확인: 커밋된 `results/porto_cctv/summary.csv` 122행과 탐지율·최악 그룹·미달 수·비용 차이가 모두 0이었다.
- **외삽:** 실행 시간이 평가 hop 수에 비례한다고 가정했다(가정, 미검증).
  - 블록 1: 534,713 hop → 약 682초
  - 블록 2: 668,001 hop → 약 852초
  - (목표, 시드) 한 쌍, 두 블록 합: 약 1,534초
  - 한 실행이 모든 방법을 함께 돌리므로 방법 10개는 실행 수를 늘리지 않는다. 목표는 설정에 하나뿐이라 목표마다 실행이 따로 필요하다.

| 경우 | 실행 수(목표 × 블록 × 시드) | 순차 실행 추정 |
|---|---|---|
| 시드 1개(기존 확증 실험과 같음) | 5 × 2 × 1 = 10 | 약 7,670초 ≈ **2.1시간** |
| 시드 10개 | 5 × 2 × 10 = 100 | 약 76,700초 ≈ **21.3시간** |

- 위 추정에 빠진 것:
  - 블록마다 한 번씩 필요한 자료·사건 단계(CSV 읽기, 관측, 전이·가시성 집합)
  - 병렬 실행
  - static·Mondrian·사후 기준은 시드와 무관하므로 생략할 여지
- 새 기간의 실제 실행 시간은 **확인 불가**다(실행 금지).
